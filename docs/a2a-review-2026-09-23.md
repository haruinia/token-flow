# A2A 组合验收（2026-09-23）

结论：沿用 CLIProxyAPI 的协议转换器，以 Responses 作为 Qoder / WorkBuddy 适配的共同中间格式。工具定义、调用和结果仍由既有 SDK 转换；参数差异使用共享字典补齐，不为每个来源与客户端组合另写转换器。审批由目标 Agent 决定，网关不产生或改写审批结论。

## Review 发现与处理

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 严格输出约束可能被忽略 | Qoder 原生构造器丢弃 `response_format`；WorkBuddy glm-5.1 实测接受严格 schema 请求，却返回 `NOT_JSON` | 共享入口拒绝不支持的结构化输出，返回 `a2a_structured_output_unsupported`，不伪造符合 schema 的结果 |
| 服务端工具可能在转换中丢失 | 原生 Chat 来源没有 Responses 内置网页搜索运行时；Codex 客户端会声明该工具 | 共享入口返回 `a2a_server_tool_unsupported`。Qoder / WorkBuddy 接入 Codex 时设置 `web_search="disabled"`，本地函数与 MCP 工具保留 |
| 渠道策略拒绝被当作通用调用/认证错误 | WorkBuddy → Codex 两次真实调用均返回业务码 `11128`，说明调用渠道未经允许 | 返回 `a2a_source_policy_blocked`；不刷新凭据重试、不隐藏来源、不绕过渠道限制。这条真实链路仍未通过 |
| 网关统一错误掩盖具体原因 | 上述能力错误原先被覆盖为通用上游失败 | 仅透出三个已知错误码及本地中文说明，其他上游内容仍脱敏 |

来源能力字典位于 `packages/contracts/a2a.ts`，自动接入、手动接入和页面提示共用。切回支持的来源时恢复原网页搜索设置；还原接口恢复原始配置。现有用户配置不会随打包自动改写，需要重新接入才应用新设置。审批权限不随能力配置放宽。

## 保留的边界

WorkBuddy → Codex 的来源策略阻断尚未解决，需使用来源明确支持的渠道或向其支持确认。未继续通过修改请求规避该限制。

测试使用隔离目录，没有替换真实用户的客户端配置或重启正在使用的 App。完整仓库测试未在本轮重跑；此前浏览器扩展集成测试的超时不属于本轮通过范围。

## 追加复测：HY4 与 Qoder（2026-09-23）

Qoder 独立应用 0.3.4 的模型页已识别现有 `token-flow · workbuddy/hy4-preview`，配置指向本机 9527 的 Responses 接口。新建临时工作区后发送真实只读请求，首次因网关未启动而出现 `ECONNREFUSED`；停止重试并启动网关后，现有 Key 和模型目录均通过验证。后续桌面自动化输入出现超时，未完成 Qoder 桌面客户端的工具闭环，不能把以下通用链路结果作为桌面验收通过。

本机 Qoder CLI 1.1.29 的模型查询及实际 `--print --model workbuddy/hy4-preview` 请求均在登录前置检查退出，提示 `Not logged in`，模型用量为零。独立应用已登录不代表 CLI 已登录。CLI 自定义模型须走 `/model → Custom`，选项以版本和账号目录为准，不能把独立应用的配置文件方案直接套给 CLI。参考：[独立应用自定义模型](https://docs.qoder.com/qoder/custom-models)、[CLI 自定义模型](https://docs.qoder.com/cli/custom-models)。本轮未操作 Qoder IDE。

随后隔离复测定位到另一个确定的转换边界：HY4 在探测请求只有 32 个输出 token 时可能只产生思考内容，并返回 `finish_reason=length`。原生 HTTP 为 200、流没有读取错误，但既有 Chat → Responses 转换器会因缺少正文和工具输出而漏发终止事件，最终被报成 502。不是该样例中的网络故障，也不是渠道策略 11128。

已通过 sidecar overlay 最小修补既有转换器：收到明确结束原因时，继续使用其原有终止事件、用量和未完成状态映射；输出上限仍返回 `incomplete / max_tokens / length`，不伪装成功，不放行不完整工具。维修连通性探测与真实验收脚本的输出上限从 32 调整为 1024，仍要求实际返回非空文本才通过。

验证证据：

- 三种客户端协议的“只有思考内容就达到输出上限”回归在修复前均失败；修复后非流式和流式终止状态均通过。
- Qoder / WorkBuddy sidecar 工具与协议回归、既有 OpenAI Chat → Responses 转换测试通过。
- 修复后真实 `workbuddy/hy4-preview`：Messages HTTP 200，Responses HTTP 200 且 completed；Pi 连通性 ready，`inspect_gateway` 工具往返 completed；真实 Claude Code 完成 Read 和后续回复，两次流式请求均 HTTP 200，准确返回临时文件内容，确认工具结果已回传。
- 真实 Codex 客户端连接模拟 WorkBuddy 上游：7 次模型请求、1 次压缩、1 次摘要，工具结果与继续回复通过。它验证客户端/网关协议链路，不改变前面真实 WorkBuddy → Codex 渠道被拒绝的记录。

维修与审批相关 14 项测试、类型检查、构建和打包通过；打包版三种接口、Key 额度及 390 / 768 / 1320 像素界面检查通过（模拟上游）；包内 sidecar 与真实工具验收使用的二进制 SHA-256 一致。

最新修复包为 `release/a2a-stream-fix/mac-arm64/token-flow.app`。测试过程中启动过上一版 `a2a-reviewed` 网关，运行中的旧包不会自动获得本次修补。
